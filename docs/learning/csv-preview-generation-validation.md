# CSV preview publication regression — Issue #65

The regression was introduced by `ce81714`, and is inherited by `1eba170`. Base `0a633b9` waited for both raw row/error responses before applying rows. The payment refactor moved a setter into parallel `loadRows`; an error could release the operation while its sibling later wrote stale rows. This was not a pre-existing main bug. The source comparison and the reviewer's classification correction are preserved in `work/issue65-regression-base-comparison-1016.json` and `work/race-classification-correction.json`.

Two distinct observed cases are recorded: a new batch could display an old batch's rows, and same-batch recovery followed by page 2 could be overwritten with an old page/cursor. The reviewer also demonstrated the new refactor's effect on customer/invoice preview; those same compatibility fixtures pass against the actual base. Original ce/1eba code, 131-unit/19-E2E/native evidence, and all RED evidence remain intact.

Rows and errors are now pure reads. A complete batch/rows/errors/cursors snapshot is published through one state update only after both reads succeed. Every preview, recovery, pagination, download and confirmation runs in an operation generation; obsolete success, failure and finalization cannot update the current view or busy state. Session/tenant/user/CSRF changes remount the private workspace, while session invalidation and unmount disable pending operations. Incomplete reads retain only a retry ID and never enable confirmation.

The reviewer's unchanged current probe contains four cases (the original two races plus customer/invoice compatibility); all four passed in the author's checkout. Source SHA256 is in `work/issue65-independent-2case-probe-binding-1017.json`. This is author verification, not an independent approval. Tracked regressions also cover atomic pending state, confirmation target, late pagination during a session change, current-session invalidation and unmount callbacks.

Targeted CSV tests: 46 passed. Entire frontend: 140 tests, typecheck, lint/mandatory guard4, API generation check and build passed (`work/issue65-concurrency-target-1018.log`, `work/issue65-all-unit-1019.log`). No backend, contract or generated type changed. Real E2E on the new fix SHA and independent reassessment remain follow-up work; old 19/native2 results are not relabeled as this fix's results. No standalone change to unrelated main is required.
