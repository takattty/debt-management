# PRとコメントの書き方

PRを開く前に、最終差分を見て[テンプレート](../.github/pull_request_template.md)を埋める。各説明は1〜3文か短い箇条書きを基本とし、変更履歴の実況やSHA・コマンドの連続貼付けを避ける。

## 本文の必須項目

| 見出し | 読者が知りたいこと |
| --- | --- |
| 概要 | どの問題を解決し、変更後に何ができるか |
| 何をやったか | 主要な変更だけ。生成物は手書き実装と区別 |
| なぜそれをやったか | 業務要件・不具合と、変更が必要な理由 |
| 何をやらなかったか | 今回の範囲外。比較候補があれば不採用理由も短く記載 |
| ユーザーへの影響 | 操作・互換性・データ移行・制約。影響がなければその理由 |
| 検証 | 対象SHA、実行した検証、結果・証拠。実行中・未実施は区別 |
| その他 | 関連Issue/業務例、依存PR、残課題、再開手順など |

比較候補・依存・生成物などがなければ「なし」と明記する。未実施の検証には理由を添え、成功したように書かない。PRで業務機能が完成していない場合、今回使える範囲と後続を明確にする。

検証は「検証 / 結果・証拠」の表にまとめる。対象SHAは一か所へ集め、CI・独立レビューをリンクする。詳細ログは本文へ貼らず、必要な件数・否定例・制約だけを書く。PRの範囲が変わったらタイトルと説明も書き直す。

## 作成前と編集後の検査

追加ツールのinstallや個人のgit hook設定は不要。GitHubの新規PR画面ではテンプレートが自動挿入され、CLI・連携APIから作る場合も同じテンプレートを使用する。

本文をUTF-8のファイルへ保存し、公開前に実行する。

```sh
node .github/scripts/pr-description.cjs --file work/pr-body.md
```

初回は `npm --prefix .github/scripts ci --ignore-scripts --cache work/npm-cache` で固定依存を用意する。Markdownはmarked 18.1.2の構文木で解析し、コード・HTML・未閉じコメント内の見出しを数えない。依存版とintegrityはlockfileへ固定し、protected gateはmainのlockfileからinstallしてPRのpackageやinstall scriptを実行しない。

GitHub CLIには `scripts/gh-repo.sh owner/repository ... --body-file work/pr-body.md` で渡す。連携toolには構造化したbody引数で渡し、本文をshell commandへ直接展開しない。

- `quality`はPRイベントの本文を検査する。見出しの欠落・重複、空欄、TODOだけの節、未記入表、コメント/コード内だけの見出しを拒否する。
- 保護されたmainの`independent-review`も、最新PR本文と最新SHAのレビュー結果を両方検査する。本文編集でも再実行するため、CI後に必須節を削除したままmergeしない。
- commit statusはPRではなくSHAに付くため、main向けの同じSHAを持つPRをまとめて判定する。一つでも本文・レビューが不合格なら全体を失敗にし、別baseのPRで成功へ上書きしない。PRの開閉・base変更も再判定の対象とする。
- merge直前にはhead/base/最新レビュー/必須チェックに加えて最新本文を読み直す。GitHubイベントの反映は非同期なので、本文編集後は再検査結果を待つ。
- 自動検査は書式の最低条件を確認するだけ。説明の正しさ・簡潔さ・読みやすさ・検証の十分さは独立レビューで確認する。

## コメント

まとまった独立レビューは[レビュー用テンプレート](../.github/comment_templates/review.md)、検証・進捗報告は[検証用テンプレート](../.github/comment_templates/verification.md)を使う。結論を先に書き、検査範囲・結果は表、残課題は短い箇条書きにする。本文の説明を繰り返す必要はなく、関連箇所をリンクしてよい。

短い指摘への返信は、対応内容・対象commit・再検証結果を数文で答えてよい。機械用の独立レビューmarkerは人向け説明の末尾に一つだけ置き、対象SHA・明示結果・blocking件数を実際のレビュー結果と一致させる。markerだけをコメントしない。

Issueのcheckpointも見出しと検証表を使い、「実施済み」「検証済み」「未実施」「阻害要因」「再開」を区別する。
