# 売掛金管理の操作手順

架空データで、ログイン、顧客・請求の登録、入金取込、消込・取消、滞留確認と督促対応までを試す手順です。必要なツール、Docker Composeの起動・停止、架空アカウントは[READMEのローカル起動](../README.md#開発用ローカル起動)に従ってください。ここでは起動コマンドを重ねて記載しません。

**この売掛金フローはmainへ統合済みです。** 実DB・画面・Composeでの確認内容と対象版は、末尾の[検証表](#検証対象と最終mainへの結合)を参照してください。

画面の記録日時と有効期限は「日本時間 / JST」で表示します。請求日・支払期日・振込日などの業務日付は、CSVに入力した `YYYY-MM-DD` のまま扱います。今回の作業は売掛金の仕上げで停止し、貸付元本は保留します。メール送信・利息計算・貸付金の操作は本手順の対象外です。

## ログインとメンバー招待

1. 起動した画面の「メールアドレス」「パスワード」を入力し、「ログイン」を押します。ローカルの初期パスワードは `.env` の `LOCAL_SEED_PASSWORD` に設定した値です。ログイン用のメールは自動送信されません。
2. 管理者がメンバーを追加する場合は「メンバー招待」を開き、「招待先メールアドレス」「付与する権限」を指定して「招待リンクを作成」を押します。経理担当者には招待操作がありません。
3. 「リンクをコピー」で、招待する相手へ手動で共有します。リンクは24時間・一回限りです。発行画面を離れると再表示できません。
4. 相手はリンクを開き、契約企業・招待先・権限・有効期限を確認します。「招待されたメールアドレス」「新しいパスワード」を入力して「招待を受けて登録」を押します。パスワードは12〜128文字で、前後空白も一部として扱います。
5. 「アカウントを登録しました」が出たら「ログイン画面へ進む」から明示的にログインします。別のアカウントでログイン中なら「ログアウトして招待を確認」を使います。ローカルで別の利用者を試すときは、別ブラウザープロファイルを使うと区別できます。

リンクが無効・期限切れ・使用済みと表示された場合は管理者へ確認してください。受諾画面の再読込で招待内容が表示されなくなった場合も、保存した元のリンクから開き直します。既に所属するメールアドレスを別の契約企業へ追加することはできません。

## 顧客を先に登録する

少数なら「顧客管理」で「顧客コード」「顧客名」を入力し、「顧客を登録」を押します。請求に使う顧客は先に登録しておきます。

複数の新規顧客は「顧客CSV取込」から登録できます。

1. 「テンプレートをダウンロード」で固定形式を確認します。初回の架空デモには [customers.csv](samples/customers.csv) を使えます。
2. 「顧客CSVファイル」を選び、「CSVをプレビュー」を押します。
3. 「プレビュー内容」の顧客コード・顧客名を確認し、エラーがなければ「全2件を確定して登録」を押します。件数部分はファイルに応じて変わります。
4. 登録完了の表示後、「顧客一覧へ」で登録結果を確認します。

顧客コードは50文字、顧客名は200文字までです。顧客CSVは新規登録専用で、既存コードが1行でも含まれると新規行も含めて全件登録できません。既存顧客は「顧客管理」の行にある「編集」から「編集中の顧客コード」「編集中の顧客名」を変更し、「変更を保存」を押します。CSVで上書きしません。

## 請求CSVを修正して全件確定する

「請求CSV取込」で「テンプレートをダウンロード」を押し、次の列順で保存します。

```csv
customer_code,invoice_number,issue_date,due_date,amount
```

UTF-8で保存します（BOM可）。日付は `YYYY-MM-DD`、金額は税込の正の円整数でカンマや小数点を入れません。支払期日は請求日以降、1ファイルは10MiB・10,000行までです。請求書番号は企業内で一意で、登録後に変更できず、取消後も再利用できません。

初回デモは上の顧客2件を登録してから、次の順に進みます。同じコード・番号を使ったデモを再度行う場合は、関連する全サンプルのコード・番号を未使用の値へ変更してください。デモのために既存データを削除する必要はありません。

1. [invoices-invalid.csv](samples/invoices-invalid.csv) を「請求CSVファイル」で選び、「CSVをプレビュー」を押します。
2. 「修正が必要な項目」で、行番号・項目・入力値・理由・修正方法を確認します。このサンプルは次の2箇所が誤りです。ヘッダーを含む元ファイルの行番号で探します。

   | 行番号 | 項目・入力値 | 修正内容 |
   | --- | --- | --- |
   | 3 | `amount` が `abc` | `200000` のような正の円整数へ修正 |
   | 4 | `due_date` が `2026-10-29` | 請求日 `2026-10-30` 以降へ修正 |

3. 必要なら「全エラーをCSVでダウンロード」を使います。「次のエラー50件」で残りも確認できます。長い入力値は先頭200文字の表示になる場合があります。エラーCSVは修正の説明用で、そのまま再取込するファイルではありません。
4. エラーが1件でもあれば、正常行も含めて**まだ1件も登録されていません**。元のCSVを修正し、ファイルを選び直して「CSVをプレビュー」を押します。修正例は [invoices-corrected.csv](samples/invoices-corrected.csv) です。
5. 新しい「プレビュー内容」で請求書番号・顧客・日付・金額・件数を確認します。「次の50行」で続きも確認できます。
6. 「全3件を確定して登録」を押し、3件の請求の登録完了を確認して「債権一覧へ」を押します。プレビューだけでは請求は登録されません。

有効期限が切れた場合は再プレビューが必要です。プレビュー後に顧客などが変わり、確定時にエラーとなった場合も、現在の登録内容に合わせてCSVを見直して新しいプレビューから確認します。

同じ内容がすでに確定されている場合は「元の取込結果を確認」で元の結果を参照します。重複を避けるために請求書番号だけを変えて再確定する操作はしません。

## 債権一覧で対象の請求を探す

「債権一覧」で「請求の状態」「顧客で絞り込む」「支払期日（開始）」「支払期日（終了）」を指定し、「条件で表示」を押します。支払期日順に50件ずつ表示し、「次の50件」で続きを取得します。開始日は終了日以前にします。

| 請求の状態 | 表示内容 |
| --- | --- |
| 有効な請求 | 初期表示。取消されていない請求と未回収額 |
| 取消済み | 取消済みの請求。元の請求額を保持し、未回収額は0円 |
| すべての状態 | 有効・取消済みの両方。各行の「状態」で区別 |

目的の請求が最初の50件にあるとは限りません。状態・顧客・支払期日を指定して探してください。「最初のページを再取得」は最後に適用した条件で取り直します。条件欄を変更したときは、改めて「条件で表示」を押して反映します。「次の50件」だけでは、入力中の新しい条件に切り替わりません。

## 請求を訂正して履歴を確認する

1. 有効な対象行の「訂正・履歴」を開き、「現在の登録内容」を確認します。取消済みの行は「履歴を確認」から同じ原本・履歴を開けます。
2. 有効で未消込の請求は「訂正後の顧客」「訂正後の請求日」「訂正後の支払期日」「訂正後の請求額（円）」を変更できます。「訂正理由」を入力し、「訂正を保存」を押します。例：`INV-GUIDE-001` を100,000円から110,000円へ訂正し、理由を「契約金額の記載誤り」とします。
3. 「請求の全履歴（原本から順に表示）」で、登録時の原本、訂正内容、理由、担当者メール、日本時間の記録日時、元の取込IDを確認します。「履歴の次の50件」で続きも取得できます。

担当者メールは、表示時点の現在の登録メールアドレスです。登録時点のメールを固定した履歴ではありません。原記録の担当者IDは「監査用の担当者ID」を開いて確認できます。

請求書番号は変更できません。取消済み、または有効な消込がある請求は直接訂正・取消できません。消込がある場合は、後述の[消込取消と請求訂正](#消込を取り消してから請求を訂正する)の順に進めます。

## 請求を取り消し、取消済みの原本を見る

1. 「請求の状態」が「有効な請求」の一覧で、対象の「訂正・履歴」を開きます。
2. 「請求を取り消す」で請求書番号・顧客・金額・支払期日・版と、取消の影響を確認し、「取消理由」を入力します。
3. 「この請求の最新内容と取消の影響を確認し、取り消す」をチェックして「請求の取消を確定」を押します。
4. 取消完了後は状態が「取消済み」、未回収額が0円となり、有効な請求の一覧から除外されます。元の請求額・番号・訂正/取消履歴は保持され、番号は再利用できません。
5. 再度履歴を見るときは「債権一覧」の「請求の状態」で「取消済み」を選び、必要に応じて顧客・期日も指定して「条件で表示」を押します。対象行の「履歴を確認」で原本と取消理由を開きます。再読込後も同じ流れで探せるので、取消前に請求IDを控える必要はありません。

## 入金から回収までの架空データを準備する

既存の顧客・請求デモから続ける場合、登録済みのC001「架空商事」とC002「架空販売」を使い、顧客CSVを再確定しません。初めて試す場合は、先にログインして [customers.csv](samples/customers.csv) の顧客2件を登録します。

「請求CSV取込」で [invoices-ar.csv](samples/invoices-ar.csv) を選び、「CSVをプレビュー」で内容を確認して「全6件を確定して登録」を押します。請求日は2026-10-30、支払期日は全件2026-11-30です。前の請求デモの `INV-GUIDE-*` とは別の番号です。

| 請求書番号 | 顧客 | 請求額 | 試す操作 |
| --- | --- | --- | --- |
| INV-AR-001 | C001 | 100,000円 | 一部入金、取消、請求訂正、再確定 |
| INV-AR-002 | C001 | 60,000円 | 2社の請求への一括入金 |
| INV-AR-003 | C002 | 40,000円 | 同じ一括入金のもう一方 |
| INV-AR-004 | C001 | 100,000円 | 手数料440円の明示 |
| INV-AR-005 | C001 | 100,000円 | 過入金20,000円の保持 |
| INV-AR-006 | C002 | 100,000円 | 名義対応と金額が一致する候補 |

すべて架空の銀行明細用データです。実在の銀行CSVとの互換性はありません。同じデモを再実行する場合は、請求書番号と入金の取引IDを未使用の値へそろえて変更し、以下の操作でも変更後の番号を使います。確定済みの請求番号・取引IDは、取消後も再利用できません。

## 入金CSVの誤りを直して全件確定する

「入金CSV取込」で「テンプレートをダウンロード」を押し、次の4列をこの順で保存します。

```csv
transaction_id,transfer_date,payer_name,amount
```

| 列 | 入力する内容 |
| --- | --- |
| transaction_id | 未使用の取引ID。1〜100文字、契約企業内で一意 |
| transfer_date | 実在する振込日を `YYYY-MM-DD` で入力 |
| payer_name | 振込名義。1〜200文字。前後空白のみ除去 |
| amount | 1〜9,007,199,254,740,991円の整数。桁区切り・小数なし |

UTF-8（BOM可）、ヘッダーあり、1ファイル10MiB・10,000行までです。取引ID・名義には改行・制御文字を入れません。0円・出金・返金は対象外です。手数料を差し引いて受け取った場合も、ここには実際の受取入金額を入力し、手数料は消込時に指定します。

1. [payments-invalid.csv](samples/payments-invalid.csv) を「入金CSVファイル」で選び、「CSVをプレビュー」を押します。
2. 「修正が必要な項目」で、元CSVの行番号・項目・入力値・理由・修正方法を確認します。行3の `amount` は `abc`、行4の `transfer_date` は実在しない `2026-11-31` です。行3を `100000`、行4を `2026-12-01` へ直します。
3. 「全エラーをCSVでダウンロード」で修正箇所を保存できます。エラーCSVは説明用なので、元の入金CSVを直します。エラーが1件でもあれば正常行も含めて全件未登録です。
4. 修正例 [payments-corrected.csv](samples/payments-corrected.csv) を選び直して「CSVをプレビュー」を押します。「プレビュー内容」で5件の取引ID・振込日・名義・金額を確認します。続きがある場合は「次の50行」「次のエラー50件」を使います。
5. エラーなしを確認して「全5件を確定して登録」を押します。完了後に「入金一覧へ」を押し、入金額と未充当額が同額であることを確認します。プレビューや取込確定だけでは請求残高は減りません。

同じ内容が確定済みなら「元の取込結果を確認」へ進みます。取引IDを変えて同じ実入金を再登録しません。CSV内の取引ID重複、既存ID、古いプレビューなどで確定できない場合は、現在の記録を確認して元CSVを見直し、再プレビューします。確定結果が不明な場合は画面を離れる前に「確定結果を確認」を使います。

## 振込名義と顧客の対応を登録する

1. 「振込名義の対応」を開き、「対応する振込名義」に `カクウショウジ`、「対応先の顧客」にC001「架空商事」を指定し、「名義対応を登録」を押します。
2. 同様に `カクウハンバイ` をC002「架空販売」へ登録します。対応の登録だけでは消込されず、残高も変わりません。
3. 「有効な名義対応」で名義・顧客を確認します。`カクウ` と `ｶｸｳ`、`KAKUU` と `kakuu`、Unicode表現の異なる文字は自動的に同一視しません。前後空白以外の揺れは担当者が確認して登録します。

同じ名義が複数顧客に対応していても、自動で一社に決まりません。誤った対応は行の「詳細・無効化」を開き、「無効化の理由」を入力し、「この原対応と理由を確認し、無効化する」をチェックして「名義対応の無効化を確定」を押します。正しい対応が必要なら別途登録します。原対応IDを控えておけば、「対応IDで原対応・無効化履歴を開く」から無効化後も登録者・日時・無効化理由を確認できます。

登録結果が不明なら「登録結果を全ページから確認」で名義・顧客・対応IDを比較します。無効化の結果が不明なら「無効化の最新詳細・処理結果を取得」を使い、すでに無効化済みの操作を再送しません。

## 理由付き候補を確認し、現金と手数料を指定する

1. 「入金一覧」で「振込日（開始）」「振込日（終了）」を `2026-12-01` にして「条件で表示」を押します。必要なら「次の50件」で続きを探します。各行の「消込を確認」を開きます。
2. 入金原本と「現在の未充当現金」を確認します。候補は名義対応、未回収額と未充当現金の一致、支払期日の早い順で提示されます。「名義対応あり／なし」「未充当現金と一致／金額不一致」と、顧客・請求書番号・期日・現在未回収額を読みます。候補には名義不一致や将来期日の請求も含まれます。
3. 名義対応が未登録、または複数顧客に一致する表示なら、入金の根拠を確認して対象を選びます。金額一致だけで顧客を決めません。チェックで選択しただけでは残高は変わりません。
4. 対象の請求を選び、「選択内容を再取得して確認」を押します。各請求の「現金（円）」「手数料（円）」を入力し、「消込理由」に判断の根拠を記入します。金額はカンマなしの円整数、手数料の初期値は0です。理由は1〜1,000文字で改行・制御文字を入れません。
5. 顧客・請求・未回収額と入力金額を比較し、「顧客・請求・現金額・明示した手数料を確認しました」をチェックして「この内容で消込を確定」を押します。確定後の未充当額は「入金一覧」、未回収額は「債権一覧」を取り直して確認します。

現金合計は正の金額で、その入金の未充当現金以下にします。各請求の現金＋手数料は正の金額で、現在未回収額以下にします。同じ契約企業内なら複数の顧客・請求へ配分できます。複数請求は一括で確定され、どれかが不正・競合なら全体を確定しません。

次の例を取引IDごとに進めます。候補の先頭位置ではなく、表の請求書番号を探して選んでください。

| 取引ID・入金額 | 選ぶ請求と入力 | 確定後に確認する残高 |
| --- | --- | --- |
| TX-AR-001・40,000円 | INV-AR-001へ現金40000、手数料0。理由「一部入金を確認」 | 請求の未回収60,000円、入金の未充当0円 |
| TX-AR-002・100,000円 | INV-AR-002（C001）へ現金60000、INV-AR-003（C002）へ現金40000、手数料は各0。理由「2社分の一括入金を明細で確認」 | 2請求とも未回収0円、入金の未充当0円 |
| TX-AR-003・99,560円 | INV-AR-004へ現金99560、手数料440。理由「明細で振込手数料440円を確認」 | 請求の未回収0円、未充当0円。入金原本は99,560円 |
| TX-AR-004・120,000円 | INV-AR-005へ現金100000、手数料0。理由「超過20000円は未充当で保持」 | 請求の未回収0円、入金の未充当20,000円 |
| TX-AR-005・100,000円 | C002のINV-AR-006へ現金100000、手数料0。名義対応と金額一致を確認して確定 | 請求の未回収0円、未充当0円 |

TX-AR-002では金額が一致する別の100,000円請求が上位に出る場合があります。2社分の一括入金という根拠を確認し、指定の60,000円と40,000円へ配分します。選択を間違えたら「選択解除」、または「最新候補を取得して選び直す」を使います。

手数料440円は自動控除されません。表のTX-AR-003は、最初から現金99560・手数料440で確定する通常手順です。**手数料0の残高を試す場合は、通常手順の確定前に選ぶ別の操作例**としてください。すでに手数料440で確定済みなら、同じ入金へ手数料0の操作を重ねません。

手数料0で確定した場合は未回収440円・未充当0円を確認します。変更するには「消込履歴」からその元操作全体を取り消し、請求未回収100,000円・入金未充当99,560円へ戻ったことを確認してから、現金99560・手数料440で再確定します。確定済みの手数料を上書きしません。過入金20,000円は未充当現金として保持し、売上・手数料・返金へ自動変換しません。

## 消込を取り消してから請求を訂正する

1. 「入金一覧」でTX-AR-001の「消込を確認」を開き、「消込履歴」で元の確定操作の請求・現金40,000円・手数料0円を確認します。「操作 （操作ID） の取消内容を再取得」を押します。
2. 「取消理由」に「請求金額の訂正のため」と入力します。対象の全請求・金額を読み、「全請求の現金と手数料をまとめて取り消すことを確認しました」をチェックして「操作全体を取り消す」を押します。
3. INV-AR-001の未回収額が100,000円、TX-AR-001の未充当額が40,000円へ戻ることを確認します。「消込履歴」には確定と取消が別々に残り、元操作と取消操作のID・実行者・理由・日時をたどれます。
4. 有効な消込がなくなったら「債権一覧」からINV-AR-001の「訂正・履歴」を開き、「訂正後の請求額（円）」を110000、「訂正理由」を「契約金額の記載誤り」として「訂正を保存」を押します。請求書番号は変えません。ほかにも有効な消込があれば、その元操作も取り消してから訂正します。
5. TX-AR-001の最新候補を取得し直してINV-AR-001へ現金40000、手数料0で再確定します。訂正後の未回収額は70,000円、入金未充当額は0円です。請求履歴の訂正と、消込履歴の旧確定・取消・再確定をそれぞれ確認します。

取消は**元の確定操作全体**が対象です。TX-AR-002を取り消すと、2社の請求が60,000円・40,000円に戻り、入金未充当が100,000円へ戻ります。一方の明細だけは取り消せません。TX-AR-003の取消なら、現金99,560円と手数料440円をともに戻し、請求未回収100,000円・入金未充当99,560円になります。入金原本の取引ID・振込日・名義・金額は変わりません。取消済みの元操作は二重に取り消せません。

消込履歴は「次の履歴50件」で続きも取得します。顧客名・請求書番号・担当者メールなどの現在の参照表示と、記録時の金額・理由・実行者ID・版・日時を区別してください。

## 未収・滞留を確認し、次回対応を引き継ぐ

1. 「督促対応」を開き、「基準日（日本の業務日）」を `2026-11-30`、「対応の状態」を「対応対象（保留を除く）」にして「候補を表示」を押します。期日当日は超過に含みません。
2. 基準日を `2026-12-01` にして再び「候補を表示」を押します。未回収のINV-AR-001は超過1日となります。一部入金直後なら60,000円、上記の訂正・再確定後なら70,000円です。完済した請求は次の取得で候補から外れます。「次の50件」で続きも確認します。
3. 対象の「対応・履歴」を開き、現在未回収額・現金充当・明示手数料を確認します。「対応メモ（共有）」へ「請求書再送の依頼。担当交代後は入金予定を確認」と入力し、「次回対応日（空欄で予定を解除）」を `2026-12-05` にして「対応メモを記録」を押します。
4. 「対応の原本履歴」で、記録した担当者・日本時間の日時・メモ・次回対応日を確認します。別担当者は同じ契約企業の自分のアカウントでログインし、同じ請求の「対応・履歴」から引き継ぎます。過去の記録は上書きせず、必要な補足を追記します。「次の50件の対応履歴」で続きを確認できます。

一覧は指定した基準日と**取得時の現在残高**による候補です。基準日を過去へ変えても、当時の残高を復元する画面にはなりません。期日未到来の未収も含めて探す場合は「債権一覧」を使います。次回対応日になっても自動通知や自動保留解除は行いません。予定の解除は対応メモとともに次回対応日を空欄にして記録します。

## 保留・解除とメール草案のコピー

1. 対応詳細の「保留・解除の理由」に「入金確認待ち」と入力し、「理由を記録して保留」を押します。債権や滞留情報は保持されます。
2. 一覧へ戻り、「対応の状態」を「保留中」にして「候補を表示」を押します。対象を開いて保留理由と次回対応日を確認します。「すべて（保留を含む）」でも探せます。
3. 解除するときは「保留・解除の理由」に「入金予定を確認したため対応再開」などと入力し、「理由を記録して保留を解除」を押します。最新状況と一覧を再取得し、保留と解除の両方が履歴に残ることを確認します。
4. 文面を用意するときは、対応詳細の「現在の残高で文面を作成」を押します。宛名・請求書番号・支払期日・現在の未回収額・件名・本文を読みます。訂正・再確定後のINV-AR-001なら70,000円です。保留中なら理由も確認し、連絡するか判断します。
5. 「表示した文面をコピー」を押します。コピー時にも現在残高を取り直すため、内容が変わった表示が出たら新しい文面を読み、もう一度押します。コピーできない場合はブラウザーの権限を確認するか、表示した件名と本文を選択して手動コピーします。宛先は利用者自身で確認します。アプリはメールを送信しません。

完済・請求取消後も対応履歴は保持されます。候補一覧から外れた請求は、「債権一覧」で「請求の状態」を「すべての状態」にして探し、「対応・履歴」から原本を開けます。必要なら完済・取消後にも対応メモを追記できます。

## 同時更新や結果不明の表示が出たとき

他の担当者が先に変更した場合（更新競合・409）、入力中の内容は保持されます。取得した最新内容と入力中の内容、履歴を比べて判断してください。

| 操作 | 最新状態を取得するボタン | 続ける前の確認 |
| --- | --- | --- |
| 顧客編集 | 「最新内容を取得」 | 「最新の登録内容」と比較し、「最新の登録内容を確認し、入力中の内容で更新する」をチェック |
| 請求訂正 | 「最新内容・処理結果を取得」 | 現在内容・履歴と入力を比較し、「最新の登録内容と履歴を確認し、入力中の内容で訂正する」をチェック |
| 請求取消 | 「取消の最新内容・処理結果を取得」 | 対象と影響を改めて確認してチェック。すでに取消済みなら再送しない |
| 消込確定の競合 | 「選択内容を再取得して確認」または「最新候補を取得して選び直す」 | 最新の顧客・請求・未回収額・未充当額で入力と選択を見直す |
| 消込取消の競合 | 元操作の「取消内容を再取得」 | 最新履歴から元操作と全明細を読み直し、取消済みなら再送しない |
| 督促対応の競合・結果不明 | 「GETで結果・最新状況を確認」 | 送信内容と最新状況・原本履歴を比較。一致記録があれば再送せず、なければ確認チェック後「最新の版で再確認に戻る」 |

消込確定の通信結果が不明なら、入力とrequest IDを保持したまま「同じ操作IDで結果を確認」を使います。取消なら「同じ取消操作IDで結果を確認」です。別の新規操作として二重送信せず、結果を確認してから続けます。結果不明の間は画面を閉じないでください。

通信が途切れた場合も、失敗したと決めつけて同じ更新を繰り返さず、まず登録状況を取得します。CSV確定では自動で結果を確認する場合があります。結果が不明のままなら、画面を離れる前に「確定結果を確認」を使います。顧客の更新完了が表示されている場合は「一覧を再取得して閉じる」を使います。

取得にも失敗する場合は入力を控えて接続を確認し、再取得します。ログイン期限切れでは画面内の業務データと入力が破棄されるため、再ログイン後に登録状況を確認してから操作します。権限拒否では管理者へ確認してください。

## 画面を離れる場合

CSV取込の画面を離れるとファイルと表示結果を破棄します。過去の取込を検索する専用一覧はありません。結果不明のまま閉じてしまった場合は、確定のし直しを急がず、担当者へ登録状況を確認してください。
