# Business examples

すべて架空の企業・金額である。金額は JPY 整数、業務日の基準は日本時間。以下は仕様・API・DB・画面テストで共通に使用する受入例であり、未実装の例を成功扱いにしない。

## Customer / Invoice / Import

| ID | 操作・前提 | 期待される結果 |
| --- | --- | --- |
| EX-I01 | Tenant A の管理者が顧客 C001「架空商事」を登録し、請求 INV-001、100,000 円、期日 2026-11-30 を登録 | 債権一覧に 100,000 円の未回収額。別セッションでも DB から再表示できる |
| EX-I02 | C001 未登録の状態で請求 CSV をプレビュー | 顧客コードの行番号・入力値・未登録の理由・顧客を先に登録する修正方法を表示。確定不可 |
| EX-I03 | ヘッダー後の物理行 2 は正常、行 3 の金額が abc、行 4 の期日が不正 | 各エラーの行・項目・値・理由・修正方法を表示しダウンロード可。正常行を含め DB 変更はゼロ。修正 CSV を新たにプレビューして確定できる |
| EX-I04 | Tenant A に同一 InvoiceNumber の行を二つ含める／既存番号を再登録 | 一意性違反を明示しバッチ全体を拒否。Tenant B の同一番号は許可し、A から B を閲覧できない |
| EX-I05 | 同じ CSV の確定を二回送信、または二担当者が同時に確定 | ImportBatch と業務記録は一度だけ作成。重複と元の取込結果を示す |
| EX-I06 | プレビュー後、確定前に参照 Customer が変更または同一番号が別操作で登録される | 確定時にも tenant・参照・一意性を検証し、全体ロールバック。古いプレビューの再確認を促す |
| EX-I07 | 消込のない請求を 100,000→110,000 円へ訂正後に取消 | 変更版と理由を履歴に残す。取消後は残高・督促候補から除外し、原請求は監査で参照可 |
| EX-I08 | 二担当者が version 1 の請求を編集し、一人が先に保存 | 後の version 1 更新は 409 相当の競合。先の変更を上書きせず、再読込して確認する導線 |
| EX-I09 | 顧客CSVに新規C002と既存C001を含める | 新規C002も登録せず全件拒否。C001の行・入力値・重複理由と、既存顧客は個別画面で変更する方法を示す |
| EX-I10 | 取消済みINV-001の再登録、または登録済み請求の番号変更を試す | 取消後も番号を予約し再利用を拒否。訂正で番号を変更できない |
| EX-I11 | 請求CSVに0円・負額、または請求日より前の支払期日がある | 該当行の金額・日付のエラーと修正方法を示し、全件非取込。正額・請求日以降へ直して再プレビューする |

CSV の行番号は利用者がファイルを修正できるよう原 CSV と対応付ける。引用符内改行を許す場合は論理レコード番号と開始物理行を区別する。固定形式の提案では引用符内改行を拒否し、理由を表示する。

## Payment / Matching / Allocation

保存則：各入金について `paymentAmount = activeCashAllocations + unallocatedBalance`。各請求について `invoiceAmount = activeCashAllocations + activeExplicitFees + outstandingBalance`。すべての構成額は非負。取消された記録は有効な残高計算へ加算しない。

| ID | 操作・前提 | 期待される結果 |
| --- | --- | --- |
| EX-M01 | C001 の請求 100,000 円に、名義「カクウショウジ」100,000 円が入金。担当者が登録した名義対応あり | 候補は金額一致・名義対応・期日を理由として表示。表示だけでは残高を変えず、担当者の確定後に未回収・未充当がともに 0 |
| EX-M02 | 請求 100,000 円に入金 40,000 円を一部充当 | 未回収 60,000 円、未充当 0。期日を過ぎれば 60,000 円が督促候補 |
| EX-M03 | C001 の INV-A 60,000 円と INV-B 40,000 円へ入金 100,000 円を一括充当 | 一つの確定操作で二つの AllocationLine を記録し、両請求 0・入金未充当 0。どちらか不正なら全部を拒否 |
| EX-M04 | 請求 100,000 円に入金 99,560 円 | 手数料を明示しなければ未回収 440 円。担当者が 440 円を明示して処理すると請求残高 0。入金事実は 99,560 円のまま |
| EX-M05 | 請求 100,000 円に入金 120,000 円 | 現金充当 100,000 円、未回収 0、未充当 20,000 円。過入金を売上や手数料へ変換しない |
| EX-M06 | 同額請求が二社にあり、名義の対応が未登録／複数候補に一致 | 曖昧さと各候補の理由を表示し、担当者が確認する。金額一致だけで顧客を決定しない |
| EX-M07 | 一部または全額の消込がある請求へ直接訂正・取消を送る | API からも拒否し、先に対象消込を取り消す操作を案内 |
| EX-M08 | EX-M03 の消込を取り消す | 二請求の残高と入金未充当が同一 transaction で復元。取消者・理由・時刻・原記録を保存。二重取消は拒否 |
| EX-M09 | 二担当者が同じ入金 100,000 円を別請求へ同時に全額充当 | 一方だけ成功。他方は競合し、残高の負値や二重充当は生じない |
| EX-M11 | 入金CSVに0円・負額・小数がある | 振込日・名義・正の円整数を検証し、該当行の修正方法を示して全件非取込。出金・返金は初期対象外 |
| EX-M12 | 同一tenantで取引IDを再取込、または消込取消後に再利用 | 既存入金を保持し、取引ID重複で全件拒否。別tenantの同一IDは許可 |
| EX-M13 | 名義「 ｶｸｳ 」「カクウ」「KAKUU」「kakuu」「é」「é」をプレビュー | 前後空白のみ除去し、幅・大小文字・Unicode表現を同一視しない。名義対応がない場合や複数一致は曖昧さを表示 |
| EX-M10 | Tenant A の入金と Tenant B の請求 ID を組み合わせて確定 | 入金・請求の双方を tenant で検証して拒否。候補・エラー・履歴から B の内容を漏らさない |

2026-10-30合意（B05/Q02）：手動登録の名義→顧客対応を優先し、未回収額一致、期日の早い順に候補を示す。名義は前後空白だけを除去し、NFC・大小文字・全半角の変換をしない。未登録・複数一致は曖昧さを示し、常に担当者が確定する。候補表示だけでは残高を変えない。
