# Requirements baseline

根拠：[Issue #1](https://github.com/takattty/debt-management/issues/1)。この文書は実装完了の宣言ではなく、合意済み範囲と検証の対応表である。仕様変更は Issue に判断を残してから反映する。

## 対象と目的

日本国内・日本円の BtoB 取引を扱うマルチテナントの債権管理 SaaS。対象は従業員 1,000 名以下、月間請求書 10,000 枚以下、経理担当者 3 名以下で、現在 Excel を使用している企業。Excel の管理限界、入金消込の手間、未回収の見落とし、督促の属人化を減らす。

売掛金管理の必須機能を優先し、その後に貸付金の元本残高管理へ進む。簡易 MVP や開発基盤だけを最終成果としない。有料継続 1,000 社は事業仮説であって開発完了条件ではない。

成果物は React / TypeScript / Java 25 / Spring / PostgreSQL / Docker / GitHub Actions の FE＋BE モノレポ。設計・実装・レビュー・検証は Cloud で実行し、ローカル起動手順を提供する。商用インフラは範囲外。

## 合意済み機能と品質の追跡

| ID | 要件 | 受入時に示す証拠 |
| --- | --- | --- |
| R01 | 顧客管理。顧客コード必須。顧客を請求より先に登録 | 顧客登録→再表示 E2E、必須・重複・他 tenant 参照の拒否 |
| R02 | 請求管理と債権登録。請求書番号必須、tenant 内で一意 | 同一 tenant 重複拒否・別 tenant 同番号許可、請求から残高への反映 |
| R03 | 顧客・請求・入金を固定 CSV 形式で取り込む | 配布テンプレート、形式の説明、各種サンプル、文字コード・列検証 |
| R04 | プレビュー後に確定。不正行があれば全件取り込まない | 混在 CSV で DB 変更ゼロ、修正後再プレビュー→確定 E2E |
| R05 | CSV エラーは行番号・項目・入力値・理由・修正方法を示す | 画面とダウンロードの一致、ユーザーが訂正箇所を特定できる業務例 |
| R06 | 入金 CSV は架空銀行明細（振込日・振込名義・金額等） | サンプルと API/DB テスト、実在の銀行仕様との混同防止 |
| R07 | 理由付き消込候補を提示し、担当者が確定 | 候補理由の表示・誤候補を確定しない操作例。完全自動確定しない |
| R08 | 一部入金と複数請求への一括入金 | EX-M02/03 の残高保存と整合性テスト |
| R09 | 手数料差額を担当者が明示して処理 | 手数料未入力時に自動控除しない、現金＋明示手数料の検証 |
| R10 | 過入金を未充当残高として保持 | EX-M05 の入金残高、請求残高との保存則 |
| R11 | 消込取消、取消後の請求訂正、変更履歴 | 取消前後の残高復元・履歴保持・二重取消拒否 |
| R12 | 消込前の請求は訂正・取消可。消込後は取消してから訂正 | API からの直接書換えも拒否、競合と取消履歴の検証 |
| R13 | 未収・滞留管理。期日超過の未回収分を督促候補にする | 基準日を固定した期限当日/翌日/一部入金/全額入金のテスト |
| R14 | 督促の対象一覧、対応履歴、次回対応日、一時保留と保留理由 | 担当者を交代しても履歴から次の対応を復元できる E2E |
| R15 | 督促メール文面作成まで。メール送信しない | 文面の確認・コピー、外部送信処理を持たないことのレビュー |
| R16 | 管理者と経理担当者。経理担当者が取込・消込・取消を単独確定。取引先ログイン不要。1 user は 1 tenant | 権限 matrix、所属の一意性、越権 API 拒否のテスト |
| R17 | 管理者がメンバーを招待 | 招待発行・有効期限・一回限り受諾・他 tenant への重複所属拒否 |
| R18 | tenant 間データ分離 | 読取・更新・CSV・候補・履歴を含む否定テストと DB 制約 |
| R19 | 操作履歴と取消履歴 | 誰が・いつ・どの対象へ・何をしたか、原記録との関連、秘密の非記録 |
| R20 | 重複 CSV 取込防止 | 二重確定・並行確定・再アップロードで重複行を生成しない |
| R21 | 同時更新競合検知 | 古い version の更新拒否、利用者が再読込して判断できる表示 |
| R22 | 確定データ変更制限 | CSV プレビュー固定、確定済みデータと取消操作の制約テスト |
| R23 | 貸付金は売掛金の後。貸付先・貸付日・当初元本・追加貸付・元本返済・取消履歴。利息計算は対象外 | EX-L01/02 の残高・取消・競合・tenant 分離 |
| R24 | 架空データで検証し、ローカル起動可能 | Docker 起動、初期化、停止・再起動、README の再現実行 |
| R25 | Cloud 開発と独立レビュー、品質 gate | 同じ SHA の各検証・別コンテキストレビュー・故意失敗時の merge 拒否 |

## 当初の対象外

- 請求書 PDF の発行（請求書は外部作成）。
- 完全自動の消込確定、督促メール送信、取引先向けログイン。
- 貸倒処理、会計連携、レポートは将来対応。
- 商用インフラ、実データによる検証、追加 API 課金、未承認の有料サービス。

| --- | --- | --- |

| Q02 | 消込候補ルールの優先順位、同名・名義揺れ、期限の重み | 明示ルールは候補案。EX-M01/06 を用いて精度・説明可能性を検証。自動確定はしない |
| Q03（解決） | 貸付元本の記録対象（追加貸付・元本返済等） | 2026-10-29 のユーザー回答：貸付先・貸付日・当初元本・追加貸付・元本返済・取消履歴。利息計算は対象外 |
| Q04（解決） | 固定 CSV の詳細形式と日付・文字コード仕様 | 2026-10-29合意：UTF-8/BOM可、headerあり、日付YYYY-MM-DD、税込JPY整数。顧客=customer_code/customer_name、請求=customer_code/invoice_number/issue_date/due_date/amount、入金=transaction_id/transfer_date/payer_name/amount。外部銀行互換を主張しない |
| Q05（解決） | 招待の配布方法 | 2026-10-29合意：管理者が期限付き・1回限りの招待リンクを手動配布。外部メール送信サービス不使用 |
| B01（解決） | 顧客CSVの既存コード | 2026-10-29合意：新規登録専用。既存コードを含むCSVは全件非取込。更新はversion付き個別画面で明示 |
| B02（解決） | 請求書番号の訂正・取消後再使用 | 2026-10-29合意：登録後変更不可・取消後も再利用不可。未消込の顧客・日付・金額は理由付き訂正可 |
| B03（解決） | 請求金額と支払期日の範囲 | 2026-10-29合意：税込の正の円整数、期日は請求日以降。0円・負額・返品/値引伝票は初期対象外 |

業務判断と技術判断を分ける。CSV の原子的確定、金額の保存則、認証済み tenant からの分離は合意済み品質条件であり、未決事項を理由に省略しない。

## 品質の完了条件

各 Issue は対象 SHA、Lint、型検査、単体、API、実 PostgreSQL 統合、画面→DB の E2E と独立レビューを持つ。該当しない検証は理由を残し、基盤の必須検証を無効化しない。少なくとも tenant 越境、重複取込、競合、確定後変更、取消、異常 CSV の一括拒否を失敗例で確認する。

月間 10,000 枚は対象顧客像であり、同時利用数や応答時間の SLA を意味しない。性能テストは 10,000 件を用いてページングとクエリを確認し、未合意の SLA を達成済みと主張しない。
